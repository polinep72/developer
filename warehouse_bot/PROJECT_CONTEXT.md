## Обзор проекта
- Телеграм-бот `WareHouseIPKBot.py` (@WareHouseIPKBot) для поиска остатков товаров на складе готовой продукции по базе PostgreSQL.
- Используются `telebot`, `psycopg2`, переменные окружения для подключения к БД и токена бота.
- Подключение к БД `warehouse` (настройка через переменную окружения `DB_NAME=warehouse`).

## Структура
- `WareHouseIPKBot.py` — обработка /start и текстовых запросов, SQL-поиск остатков по трем типам продукции.
- `Dockerfile` — образ Docker для запуска бота в контейнере.
- `docker-compose.yml` — конфигурация для запуска бота через Docker Compose.
- `requirements.txt` — зависимости Python проекта.
- `DOCKER_SETUP.md` — инструкция по развертыванию в Docker.
- (Контекстные файлы) `PROJECT_CONTEXT.md`, `SOLUTIONS_HISTORY.md`, `CHAT_HISTORY.md`, `SYNC_INSTRUCTIONS.md`, `CHANGELOG.md`, `README.md`.

## Текущее состояние
- Бот переделан для работы со складом готовой продукции (БД `warehouse`).
- Поиск остатков ведется по трем типам продукции (ms/m/pp) через нормализованные таблицы:
  - `elements` / `element_types` — номенклатура и типы
  - `invoices` / `consumptions` — приход/расход для всех типов (фильтрация по `element_type_id`)
- Поиск осуществляется по наименованию товара (`elements.name`) или коду кристалла (`chips.chip_code`).
- Остатки рассчитываются как разница между приходом (`SUM(invoices.quan)`) и расходом (`SUM(consumptions.quantity)`), по каждой поставке (по `item_id`) с сортировкой FIFO.
- Поиск показывает каждую поставку отдельно с её остатком, датой прихода и номером накладной (без группировки по характеристикам).
- Результаты сортируются по дате прихода по возрастанию (FIFO - First In First Out) - самые старые поставки первыми, что помогает определить, какие элементы расходовать первыми.
- Результаты отображаются отдельными секциями для каждого типа продукции с разделителями.
- Бот поддерживает запуск в Docker-контейнере (Dockerfile, docker-compose.yml).
- Бот защищен от SQL-инъекций: используется параметризованный запрос (psycopg2 автоматически экранирует значения через %s) и дополнительная валидация входных данных (validate_search_term: ограничение длины, удаление опасных символов SQL).
- Нормализована структура БД: созданы таблицы с английскими названиями `element_types` и `elements` (объединение `names_ms/names_m/names_pp`). Таблица `elements` включает все поля из исходных таблиц: `id`, `element_type_id`, `name`, `description`, `price`, `created_at`, `updated_at`. Бот использует нормализованную структуру через JOIN с `element_types` вместо трех отдельных таблиц. Миграция выполнена: перенесено 276 записей со всеми полями (description, price).
