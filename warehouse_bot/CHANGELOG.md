## [1.0.0] - 2025-12-19
### Changed
- Бот переделан для работы со складом готовой продукции (БД `warehouse`).
- Изменена логика поиска: теперь поиск ведется по наименованию товара (таблицы `names_ms`, `names_m`, `names_pp`) или коду кристалла (`chips.chip_code`).
- Изменена структура таблиц: используются `invoice_ms/consumption_ms`, `invoice_m/consumption_m`, `invoice_pp/consumption_pp` вместо `invoice/consumption`, `invoice_p/consumption_p`, `invoice_f/consumption_f`.
- Обновлен расчет остатков: остатки рассчитываются как `SUM(quan) - SUM(quantity)` и группируются по комбинации наименование + кристалл + корпус (для модулей и ПП также учитывается ПП).
- Обновлен формат ответа: результаты отображаются отдельными секциями для каждого типа продукции (Микросхемы, Модули, ПП).
- Обновлено приветственное сообщение бота под новый функционал.
- Добавлено логирование и обработка ошибок для диагностики проблем при запуске.
- Файл переименован из `@HowManyCrystals_bot.py` в `WareHouseIPKBot.py` (бот в Telegram: @WareHouseIPKBot).
- Исправлена ошибка в SQL-запросе: добавлено получение name_id, chip_id, body_id из таблиц consumption для корректной работы FULL OUTER JOIN.
- Добавлена поддержка Docker: созданы Dockerfile, docker-compose.yml, requirements.txt, .dockerignore и DOCKER_SETUP.md.
- Бот успешно собран и запущен в Docker-контейнере warehouse-ipk-bot.
- Добавлена дата прихода в результаты поиска для реализации FIFO (First In First Out): обновлен SQL-запрос с добавлением MIN(ad.date) для получения самой ранней даты прихода, результаты сортируются по дате прихода (самые старые первыми), дата прихода отображается в формате DD.MM.YYYY для каждой позиции.
- Добавлен номер накладной в результаты поиска: обновлен SQL-запрос с подзапросом для получения номера накладной (invoice.invoice_id) для самой ранней даты прихода каждой позиции.
- Изменена логика поиска: теперь показываются все поставки отдельно с их остатками (без группировки по характеристикам). Функция fetch_stock возвращает список кортежей вместо словаря. Каждая поставка (item_id) отображается отдельно с её остатком, датой прихода и номером накладной. Результаты сортируются по дате прихода по возрастанию (FIFO) - самые старые поставки первыми.
- Исправлена ошибка SQL-запроса: в item_balances использовались cons.name_id, cons.chip_id, cons.body_id, которых нет в consumption_sum. Изменен FULL OUTER JOIN на LEFT JOIN, в item_balances используются только inv.name_id, inv.chip_id, inv.body_id из invoice_sum.
- Добавлена дополнительная защита от SQL-инъекций: функция validate_search_term() для валидации входных данных (ограничение длины до 200 символов для защиты от DoS, удаление опасных символов SQL). Код уже был защищен параметризованными запросами (psycopg2 автоматически экранирует значения), теперь двухуровневая защита: параметризованные запросы + валидация входных данных.
- Подготовлена нормализация структуры БД: создан SQL-скрипт `database/normalized_schema.sql` для создания таблиц `типы_элементов` и `элементы` (объединение `names_ms/names_m/names_pp`), скрипт миграции `scripts/migrate_names_to_normalized.py` для переноса данных, адаптированная версия бота `WareHouseIPKBot_normalized.py` для работы с нормализованной структурой, инструкция `MIGRATION_INSTRUCTIONS.md` по поэтапной миграции. Преимущества: единая логика работы, легкое добавление новых типов, упрощение кода, соответствие принципам нормализации БД (3NF).
- Исправлены проблемы нормализации БД: переименованы таблицы на английские названия (`element_types`, `elements` вместо `типы_элементов`, `элементы`) для избежания проблем с кодировкой в будущем. Добавлены недостающие поля `description` и `price` в таблицу `elements` (перенесено 276 записей из `names_*` со всеми полями, 206 записей имеют `price`). Обновлен код бота для работы с английскими названиями таблиц. Создан скрипт `scripts/migrate_to_english_schema.py` для миграции данных со всеми полями. Результат: полностью нормализованная структура с английскими названиями и всеми необходимыми полями.
