Изменена логика поиска: поиск ведется по наименованию товара (names_ms, names_m, names_pp) или коду кристалла (chips.chip_code). Обновлена структура таблиц: используются invoice_ms/consumption_ms, invoice_m/consumption_m, invoice_pp/consumption_pp. Остатки рассчитываются как разница между приходом (quan) и расходом (quantity), группируются по комбинации наименование + кристалл + корпус (для модулей и ПП также учитывается ПП). Результаты отображаются отдельными секциями для каждого типа продукции.
- 2025-12-19: Исправлена ошибка в SQL-запросе: добавлено получение name_id, chip_id, body_id из таблиц consumption через MAX() для корректной работы FULL OUTER JOIN. Улучшено логирование ошибок.
- 2025-12-19: Добавлена поддержка Docker: созданы Dockerfile, docker-compose.yml, requirements.txt, .dockerignore и DOCKER_SETUP.md. Бот успешно собран и запущен в Docker-контейнере warehouse-ipk-bot.
- 2025-12-19: Добавлена дата прихода в результаты поиска для реализации FIFO (First In First Out). Обновлен SQL-запрос: добавлен MIN(ad.date) для получения самой ранней даты прихода для каждой позиции. Результаты сортируются по дате прихода (самые старые первыми). Дата прихода отображается в формате DD.MM.YYYY для каждой позиции в результатах поиска.
- 2025-12-19: Добавлен номер накладной в результаты поиска: обновлен SQL-запрос с подзапросом для получения номера накладной (invoice.invoice_id) для самой ранней даты прихода. Номер накладной отображается для каждой позиции.
- 2025-12-19: Изменена логика поиска: теперь показываются все поставки отдельно с их остатками (без группировки по характеристикам). Функция fetch_stock возвращает список кортежей вместо словаря. Каждая поставка (item_id) отображается отдельно с её остатком, датой прихода и номером накладной. Результаты сортируются по дате прихода по возрастанию (FIFO) - самые старые поставки первыми.
- 2025-12-19: Исправлена ошибка SQL-запроса: в item_balances использовались cons.name_id, cons.chip_id, cons.body_id, которых нет в consumption_sum. Изменен FULL OUTER JOIN на LEFT JOIN (остаток не может быть положительным без прихода), в item_balances используются только inv.name_id, inv.chip_id, inv.body_id из invoice_sum.
- 2026-01-16: Добавлена дополнительная защита от SQL-инъекций: функция validate_search_term() для валидации входных данных (ограничение длины до 200 символов для защиты от DoS, удаление опасных символов SQL). Код уже был защищен параметризованными запросами (psycopg2 автоматически экранирует значения), добавлена двухуровневая защита: параметризованные запросы + валидация входных данных.
- 2026-01-16: Подготовлена нормализация структуры БД: создан SQL-скрипт normalized_schema.sql для создания таблиц типы_элементов и элементы (объединение names_ms/names_m/names_pp), скрипт миграции migrate_names_to_normalized.py для переноса данных, адаптированная версия бота WareHouseIPKBot_normalized.py для работы с нормализованной структурой, инструкция MIGRATION_INSTRUCTIONS.md по поэтапной миграции. Преимущества: единая логика работы, легкое добавление новых типов, упрощение кода, соответствие принципам нормализации БД (3NF).
